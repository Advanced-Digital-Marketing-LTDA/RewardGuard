1. Preserve all code/test rules and thresholds; run engine tests and review the exact immutable action source. Publish a stable release only with separate authorization. Confirm its tag resolves to the tested action SHA and its exact-SHA CI passed.
2. Pin both central action uses to that SHA with the same version comment. Review shared workflow and publisher/policy source. Secret-free candidate validation runs workflow contracts, real-Git snapshot fixtures and actual inline publisher fake-API tests; it receives no provider credentials.
3. Review immutable shared candidate C, then prepare a real public consumer with trusted-base publication mappings, matching `run_tests` / `run-tests`, named secrets and permissions. Use `contents: read`, `pull-requests: write`, `checks: write`; add `actions: read` when tests are enabled. The shared judge inherits this caller bound; base/tests remain read-only. Use PR events plus default-branch pushes and PR/ref concurrency. Keep default-branch coverage.
4. A trusted, reviewed consumer caller pins `workflows/.github/workflows/rewardguard.yml@C` literally. Do not execute proposed workflow/action code alongside provider credentials. Run mapped public synthetic content first with a cache miss, then replay identical semantics with restored records. Retain report/run/action/head/base/policy identities and source review. Include clean, warning and failure results and explanation reuse; missing or changed-identity cache records must remain explicit. Expected finding-bearing runs can conclude failure with no execution errors; never suppress their failures to make a canary green.
5. Authenticate each report artifact `rewardguard-review-<run_id>-<attempt>` and sole `rewardguard.json` by GitHub run/attempt/repository metadata and archive SHA-256. Verify `referenced_workflows` proves C ran, report `action_revision` proves the pinned action, and jobs show successful upload/publication steps. Compare first/replay unit/rule identities, probabilities, coverage, findings and details. Record hits separately from archive restores; inspect provider evaluation/explanation counters. Origin establishes provenance, not model precision or test honesty.
6. Add reviewed acceptance receipt in later main commit P. It references C rather than its own SHA. Publisher verifies C ancestry, identical shared workflow and publisher/policy bytes, exact-P offline validation, matching release/tag/CI, authenticated first/replay reports and current protection/channel state. Any relevant source/rules change invalidates proof. Pending/absent proof blocks promotion. Current-main review through old `@v0` is additional CI, never candidate execution proof.
7. After separately authorized promotion, read back `v0`, then inspect a new real consumer run's resolved shared workflow/action SHAs and report/cache behavior. Queued runs may retain older revisions. Engine merge alone does not complete rollout. Track all 13 accessible callers; inventory is not organization-wide completeness. No caller files or settings were changed here.
