## Implemented boundary and extraction

- Added validated trusted-base `[[content.publications]]` declarations. Stable IDs, source globs, website artifact type, local route, explicit publication/draft opt-in, declared dependency IDs, context-code evidence bindings, and JSON reader-field paths are validated. Duplicate IDs, unknown keys/types/dependencies, cycles, invalid routes and path escapes fail configuration parsing. Ambiguous overlapping source declarations fail closed in selection.
- Default mappings are empty. A README, arbitrary Markdown, internal docs, or JavaScript strings do not become publication content through include patterns or a model. Existing include/source_include only narrow an explicit declaration. Required case-insensitive internal/test/agent/tool/generated/credential exclusions remain enforced even with `exclude=[]` and `evidence_exclude=[]`. Git nonregular modes, including symlinks, are rejected before reading.
- All extraction reads bounded Git blobs; no worktree content, branch execution, imports, sibling-source guessing, automatic internal documentation, installed skills, generic file inventories, or Git-log context enters the content model.
- Added conservative reader-unit extraction for Markdown/MDX headings, paragraphs, simple frontmatter, links and alt; HTML text paragraphs preserving inline markup/entities, reader attributes and static JSON-LD; explicitly declared JSON string fields; static Svelte/Vue/Astro and direct JSX return markup. Unsupported dynamic expressions, code fences, unresolved templates, unsupported formats, ambiguous/escaped JSON anchors and oversized complete units produce explicit `not_evaluated` limitations. JSON repeated values are omitted when exact field location cannot be established, rather than mis-anchored. Credential-redaction placeholders never become source anchors.
- Unit semantic identity excludes source path, absolute line, commit and package version. Exact extracted fragments use unit-relative anchors and separate source line maps. HTML inline fragments can share one source line without losing relative quotation identity. Replayed findings use the current path/line.
- Added `content_publications.manifest(...)` for a local-only `--plan` consumer. It returns current artifacts/units, exclusions/reasons, deleted routes, direct/transitive dependencies, baseline units, semantic/source change classification, cache-only decisions and cache configuration availability. No provider construction or credentials are needed. Full wire/schema documentation is in `public-content-api.md` beside this report.

## Scoped engine and incremental behavior

- Removed the model `content_task` gate. Publication eligibility is deterministic metadata, without a fabricated probability. Model applicability only runs for declared public units.
- All 243 catalog signatures remain. `content_rules.inventory()` supplies per-rule semantic revisions, public artifact types and disposition: 122 `public_enabled`, 34 `adopted_policy_only`, 87 `outside_website`. Research/brief/SEO-research/ad/email/SMS/sponsorship/comms/sales/report/listing packs are outside this initial website scope. No presence-based activation of research/email/ad/strategy rules occurs. Adopted-policy-only rules with no usable bound P are locally not applicable and make no model call.
- Each unit/rule request is independent. Editing one rule does not change other rule requests. Pure copy checks consume only the unit/heading. Whole-artifact/order, editing-baseline, declared transitive dependency and route/reference inputs enter only rules that require them. Evidence is filtered by each rule's actual evidence contract; unrelated bound policies, arbitrary repository inventory and PR text do not invalidate independent checks. PR intent is supplied only for named intent-contract checks.
- Source state labels the reader sequence as potentially partial, with an explicit completeness flag and omission reasons. C is contract-specific and available only for `CG_SECTION_PROMISE_MISMATCH` / `CG_SEARCH_ANSWER_COVERAGE` when complete supported authored-text extraction and declared dependencies establish that exact subject; selected JSON fields/HTML attributes never establish a complete record. All other C contracts remain unverified by this extractor. Source observations never establish rendering, live destination availability, measurements, or external truth. Existing evidence alternatives, conditional readiness, independent field propositions, fixed 0.60/0.80 grading and Jev authority remain intact.
- Reconstructs findings/coverage from currently present units. Deleted paragraphs do not leave stale findings. A one-paragraph edit reissues only that unit's independent checks; movement re-anchors cached results. Relative/absolute links resolve against declared public routes when route removal/change schedules referencing units. Shared dependency changes expand only declared transitive dependants. Unchanged static reader output after a script/CSS/source-location edit is cache-only, not a model regrade.
- Added authenticated completed unit/rule records, implemented with the existing `ReviewCache` under a separate namespace. Immutable records serve as the recoverable index; no unsigned index authorizes results. Records are shape/probability/grounding validated on replay and cannot lose a warning/failure by omitting a finding. Completed local/request/explanation results retain their separate lifecycles. Clean completed records survive a Haiku-only configuration change; warning/failure replay invalidates changed explanation inputs and the raw Jev cache then recovers the grade without a paid Jev call. Pure move/implementation-only cache misses never cause provider work.
- Final-result replay is observable: coverage rows retain their normal status plus `reused: true`, and `ContentResult.result_cache_hits` counts completed unit/rule hits separately from Jev request-cache hits.
- Added coverage status `unchanged`: no new reader content and no reusable completed record, explicitly unreviewed rather than a required missing-evidence gap or a clean verdict. An all-unchanged/unadopted result has status `skipped`. Real extraction/evidence gaps remain `not_evaluated`, including alongside evaluated scopes.
- Provider or explanation failure returns `ContentResult.status='error'`, explicit errors, and completed findings/coverage. A Jev finding is retained before explanation, so Haiku failure cannot clear it. Parent approved a one-line CLI compatibility change (`rep.errors.extend(content.errors)`); it is included. No other CLI/action/workflow work was done. Content-check and Markdown report compatibility now describe deterministic eligibility and accept `unchanged`.

## Explicit limits and handoff

- This remains signed local/Actions cache reuse. Durable and concurrent cross-run exactly-once storage is deferred to REWARD-1. No automatic TTL was added; the existing explicit max-age setting is honored.
- Manifest cache availability only reports configured/disabled. It does not infer authentic hits or historical invalidation causes without signing credentials and an exact request/result lookup. Runtime cache miss reasons come from actual lookup/validation evidence.
- JSON supports declared string fields and rejects ambiguous/escaped anchors. JS/TS metadata objects, arbitrary implementation strings, dynamic template output, frontend execution, YAML copy records, and nontext/visual content are not silently generalized into review. Static extraction limitations remain explicit.
- Configured evidence is whole-file and bound by code; absent/oversized/denied evidence stays missing. There is no heuristic automatic context discovery. R/M/S are scoped repository assertions requiring the existing matching/readiness check, not independent external verification.
- A cache-only untouched warning with changed explanation inputs preserves its authenticated Jev probability/finding, omits stale explanation details and reports `explanation_status=not_evaluated` with the reason, without making a provider call. On normal changed-content review, raw authenticated Jev records recover the grade and the changed explanation runs. This boundary is documented, not claimed to be a refreshed untouched explanation.
- Current plan lists all declared sources and has a 160000-byte per-blob read cap. It is local and deterministic; very large repositories may need future manifest/index optimization. No new budget work was introduced.
- `content_results.py` uses explicit engine/extractor/final-record/prompt revisions. Semantic prompt changes require bumping the corresponding revision; unrelated package releases do not invalidate content results.
- Follow-on CLI/action task owns new flags/defaults, `--plan` rendering, pinning/security/ref/cache transport, and diagnostics presentation. Its integration points are the manifest API, `eligibility` flags, `unchanged` coverage, `errors`, and `result_cache_hits`/`reused` metadata.
